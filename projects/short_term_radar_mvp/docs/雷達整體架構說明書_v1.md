# 雷達整體架構說明書 v1

更新日期：2026-05-12

這份文件是短線雷達搬出牛頭人資料夾前的整理版。目標是讓後續搬家、開新倉庫、補資料、跑測試時，不會再搞混「雷達本體」、「外部資料來源」、「本機資料」和「牛頭人專案」的邊界。

## 一句話結論

短線雷達本體已經集中在：

```text
projects/short_term_radar_mvp/
```

目前已能跑出「簡版短線雷達」：使用台股日線資料做掃描、分數、分級、報告、回測與基準比較。

它還不是完整雷達。完整雷達還需要把月營收、籌碼、注意處置、重大訊息、公司行動、估值、交易日曆等資料格跑過真實資料小測試，並寫入整理後資料。

## 專案邊界

短線雷達本體包含：

```text
short_term_radar/                  雷達程式本體
tests/                             測試
configs/short_term_radar/          設定範本
docs/                              規格、交接、架構文件
reports/short_term_radar/          範例輸出與已驗證報告
data/quality/.gitkeep              空資料夾佔位
README.md                          專案入口
SHORT_TERM_RADAR_HANDOFF.md        交接與目前狀態
.gitignore                         本專案自己的忽略規則
pytest.ini                         測試設定
```

短線雷達本體不包含：

- 牛頭人主專案的根目錄檔案。
- 牛頭人主專案的 `assets/`、`dashboard/`、`overlay/`、`records/`、`tools/` 等資料夾。
- 本機五年日線資料。
- 永豐或其他券商登入資訊。
- 本機設定檔 `configs/short_term_radar/local.yaml`。
- `data/raw/`、`data/processed/`、`data/tmp/`。
- `.env`、憑證、權杖、券商紀錄、快取、資料庫暫存檔。

## 目前可用程度

目前可用的是「簡版短線雷達」。

已驗證可做：

- 每日候選股掃描。
- 價量特徵計算。
- 分數計算。
- 分級與風險標記。
- 文字報告產生。
- 月度前幾名回測。
- 隨機、突破、量能、均線等基準比較。
- 資料覆蓋率與新鮮度檢查。

最近一次已驗證結果：

- 測試：`70 passed`
- 編譯檢查：通過
- 掃描日期 `2026-04-30`：產生 50 檔候選股
- 回測區間 `2021-05-01` 到 `2026-04-30`：產生 1083 筆雷達候選紀錄
- 目前模式：`simple_price_volume_mode`

## 整體流程

短線雷達的主流程是：

```text
本機設定
  ↓
資料來源收集
  ↓
資料正規化
  ↓
整理後資料表
  ↓
資料轉接器
  ↓
特徵計算
  ↓
掃描流程
  ↓
分數與分級
  ↓
報告、回測、資料品質檢查
```

對應程式位置：

```text
short_term_radar/cli/              命令列入口
short_term_radar/data_sources/     資料來源、正規化、品質檢查、儲存
short_term_radar/adapters/         整理後資料轉成雷達可用輸入
short_term_radar/features/         價量、營收、籌碼、催化、風險等特徵
short_term_radar/scoring/          分數、分級、理由產生
short_term_radar/backtest/         回測與基準比較
short_term_radar/pipeline.py       掃描主流程
short_term_radar/data_loader.py    資料載入
short_term_radar/config.py         設定載入
short_term_radar/schemas.py        資料結構
```

## 資料格狀態

| 資料格 | 目前狀態 | 用途 | 下一步 |
|---|---|---|---|
| 價格資料格 `PRICE_SLOT` | 已安裝 | 日線、成交量、均線、突破、回測標籤 | 搬家後確認本機日線路徑仍可讀 |
| 股票宇宙資料格 `UNIVERSE_SLOT` | 部分完成 | 股票代號、名稱、產業、上市櫃資訊 | 補完整官方公司基本資料並寫入整理後資料 |
| 月營收資料格 `REVENUE_SLOT` | 部分完成 | 營收轉折、營收成長、避免未來資料洩漏 | 跑本機小範圍真實資料測試，再回補 |
| 籌碼資料格 `CHIP_SLOT` | 部分完成 | 三大法人、融資融券、借券、籌碼擁擠 | 三大法人與融資融券需跑真實資料小測試 |
| 注意處置資料格 `SURVEILLANCE_SLOT` | 部分完成 | 注意股、處置股、避免追高風險 | 補官方來源或確認券商唯讀資料可用性 |
| 催化事件資料格 `CATALYST_SLOT` | 部分完成 | 重大訊息、題材催化、事件分類 | 補真實官方資料欄位對應與回補 |
| 公司行動資料格 `CORPORATE_SLOT` | 部分完成 | 除權息、減資、分割等影響價格的事件 | 補真實官方資料欄位對應與回補 |
| 財報資料格 `FINANCIAL_SLOT` | 部分完成 | 財報品質、槓桿、財務風險 | 正規化已有，尚未完整接進掃描評分 |
| 估值資料格 `VALUATION_SLOT` | 部分完成 | 本益比、股價淨值比、殖利率、市值近似值 | 補真實官方資料欄位對應與回補 |
| 交易日曆資料格 `CALENDAR_SLOT` | 部分完成 | 覆蓋率、回測交易日、排除週末與休市日 | 目前可由日線推交易日，仍需官方交易日曆 |

## 運作模式

目前有三種模式。

### 簡版價量模式

程式名稱：`simple_price_volume_mode`

可用條件：

- 價格資料可讀。
- 股票宇宙資料可以完整或部分可用。

可以做：

- 掃描候選股。
- 回測。
- 基準比較。
- 產生報告。

限制：

- 月營收未完成時，不能進入最高信心分級。
- 籌碼、處置、事件、估值等加分或風控訊號可能缺席。

### 半完整模式

程式名稱：`semi_full_short_term_radar`

可用條件：

- 月營收資料格已安裝。
- 注意處置資料格已安裝。

意義：

- 可以開始把營收轉折與風險排除納入主流程。
- 比簡版價量模式更接近真正的短線雷達。

目前狀態：

- 還沒有達成，因為月營收與注意處置仍是部分完成。

### 完整模式

程式名稱：`full_short_term_radar`

可用條件：

- 價格、股票宇宙、月營收、籌碼、注意處置、催化事件、公司行動、估值、交易日曆都必須是已安裝。

保護規則：

- 部分完成的資料格不能觸發完整模式。
- 已有測試防止 `full_short_term_radar` 被部分資料格誤觸發。

目前狀態：

- 還沒有達成。

## 重要命令

所有命令目前都從這裡執行：

```powershell
cd projects\short_term_radar_mvp
```

搬成獨立專案後，就從新的專案根目錄執行。

測試：

```powershell
py -3.14 -m pytest -q tests\short_term_radar
py -3.14 -m compileall -q short_term_radar tests\short_term_radar
```

```powershell
py -3.14 -m short_term_radar.cli.collect `

  --dataset monthly_revenue `
  --market all `
  --start-month 2026-01 `
  --end-month 2026-03 `
  --source official `
  --dry-run
```

```powershell

  --market TWSE `
```

```powershell
  --config configs/short_term_radar/default.yaml `

  --top-n 20 `
  --horizon-days 126 `
  --target-multiple 3 `
  --include-baselines `
  --random-seed 42 `
```

## 搬家清單

搬出去時要帶走：

- `.gitignore`
- `README.md`
- `SHORT_TERM_RADAR_HANDOFF.md`
- `pytest.ini`
- `short_term_radar/`
- `tests/`
- `configs/`
- `docs/`
- `reports/short_term_radar/`
- `data/quality/.gitkeep`

搬出去時不要帶走：

- `configs/short_term_radar/local.yaml`
- `data/raw/`
- `data/processed/`
- `data/tmp/`
- `.env`
- 憑證
- 權杖
- 券商紀錄
- 快取
- 牛頭人主專案的其他資料夾

搬家後要立刻檢查：

1. 新資料夾可以直接執行測試。
2. 文件裡的工作目錄不再寫成 `projects\short_term_radar_mvp`，而是新的專案根目錄。
3. `.gitignore` 仍會排除本機設定與資料產物。
4. 沒有任何憑證、資料庫、原始資料、整理後大資料被放進新倉庫。
5. `README.md` 的入口順序要先指向本文件。

## 搬家後建議順序

1. 建立新的正式資料夾。
2. 把 `projects/short_term_radar_mvp/` 內容複製過去。
3. 在新資料夾建立獨立版本控制。
4. 先跑測試與編譯檢查。
5. 建立本機設定檔，但不要上傳。
6. 跑簡版價量掃描，確認搬家沒有破壞基本功能。
7. 再逐格補月營收、籌碼、注意處置、事件、公司行動、估值、交易日曆。

## 目前最重要的風險

- 舊任務文件有些中文編碼已經亂掉，本文件應作為搬家時的乾淨入口。
- 官方資料來源有些只是候選網址，不能因為有網址就把資料格標成已安裝。
- 本機資料可以讓簡版雷達跑，但完整雷達需要整理後資料表真的存在。
- 永豐或任何券商介面只能作為唯讀輔助資料，不應變成主資料儲存或交易入口。
- 搬家後若沒有更新文件中的工作目錄，後續執行者會被舊路徑誤導。
